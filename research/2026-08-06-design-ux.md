# Deep-dive: UI/UX and product design for AI-assisted development

**Date:** 2026-08-06. **Trigger:** user request to research SOTA UI/UX and product design practices
specifically for AI-assisted development, evaluate current design capabilities against them, and
integrate/document what's actually worth adopting — not just survey the space.

## The core problem: "AI slop design"

There's a well-documented, named failure mode: AI-generated UIs converge on the statistical center
of their training data — Tailwind UI's ~2019 defaults (Inter font, indigo→purple gradients, 3-card
grids, glassmorphism, colored left-border strips, bounce easing) got copied into millions of
tutorials and became the default output of every model, regardless of what the product actually is.
The fix isn't "try harder" prompting — it's giving the agent an explicit constraint framework
*before* generating: a purpose/audience/aesthetic-direction pass, a token system (palette, type
pairing), a list of forbidden default patterns, and a self-critique loop before calling it done.
Sources: [SmoothUI](https://smoothui.dev/blog/ai-design-slop),
[Jack Pearce](https://www.jackpearce.co.uk/notes/purple-gradient-ai-aesthetics/),
[BrainGrid](https://www.braingrid.ai/blog/design-system-optimized-for-ai-coding),
[MindStudio](https://www.mindstudio.ai/blog/claude-design-avoid-generic-ai-aesthetics).

**Grounded locally, not just theoretically:** Compass's `app/globals.css` is still the untouched
`create-next-app` scaffold — Arial fallback in the font stack, no type scale, no token system,
default Geist/black-white theme. It's a textbook case of the exact gap this research is about,
found by checking, not assumed.

## Findings by topic

1. **Generic AI aesthetics** — see above. Anthropic's own `frontend-design` plugin (in
   `claude-plugins-official`, previously uninstalled here) directly implements the fix: a
   brainstorm → token-plan → self-critique-against-brief → build → critique-again workflow, plus a
   named list of the three current AI-design clusters to actively avoid (warm-cream/serif/terracotta;
   near-black/single-accent; broadsheet/hairline-rule). It also bakes in an accessibility floor
   (keyboard focus visible, reduced motion respected) and copywriting guidance (active voice,
   consistent verb-to-toast naming, no filler). **Impact: high, effort: low** — official, free,
   already available.

2. **Design systems for agent workflows** — 2026 consensus stack for AI-assisted frontend work:
   token-first architecture (`design tokens → Tailwind bindings → shadcn/Radix primitives →
   composed features`), never hardcoded literals, because a token doc gives an agent something
   concrete to stay consistent against across a session instead of re-deriving choices each time.
   Compass already uses this general stack (Tailwind + Next.js); the actual gap is a written
   tokens/constraints doc, not new tooling. Source:
   [Shadi Sbaih](https://shadisbaih.medium.com/building-a-scalable-design-system-with-shadcn-ui-tailwind-css-and-design-tokens-031474b03690).

3. **Accessibility** — WCAG 2.2 AA is the current legal/practical baseline (cited by both the EU
   Accessibility Act and US DOJ rules). New in 2.2: Focus Appearance, Dragging Movements, Target
   Size (24×24px minimum), Redundant Entry. What AI-generated code specifically tends to miss:
   full keyboard-nav coverage, target size, ARIA on custom (non-native) components, and
   contrast — where APCA is a more accurate check than the plain WCAG ratio for small/bold text
   specifically. Sources:
   [Level Access WCAG 2.2 checklist](https://www.levelaccess.com/blog/wcag-2-2-aa-summary-and-checklist-for-website-owners/),
   [addyosmani/agent-skills accessibility checklist](https://github.com/addyosmani/agent-skills/blob/main/references/accessibility-checklist.md).

4. **Prototyping/iteration workflow** — the "reflection loop" pattern (generate → render →
   screenshot → critique against a rubric → revise, capped iterations) is directly executable today
   with Compass's existing Playwright E2E setup (`scripts/browser/`, built for the Wallet-sync
   feature's login-flow testing). This is a prompting/workflow habit, not a new tool purchase.
   Source: [Agentic Coding Handbook](https://tweag.github.io/agentic-coding-handbook/WORKFLOW_VISUAL_FEEDBACK/).

5. **Lightweight IA/UX heuristics for solo work** — Nielsen's 10 usability heuristics, run as a
   ~10-minute structured self-review pass before shipping a UI surface, is an established
   substitute for a real user-research team on solo/small projects. Source:
   [Eleken heuristic checklist](https://www.eleken.co/blog-posts/a-checklist-for-ux-design-audit-based-on-jakob-nielsens-10-usability-heuristics).

6. **Design-to-code MCP servers** (Figma official Claude Code integration shipped Feb 2026;
   Framelink as the open-source community standard) — **evaluated and explicitly not adopted.** No
   existing Figma/Canva usage anywhere in this setup, solo dev, and Compass's UI doesn't originate
   from design files — it's built directly in code. Revisit only if that changes. Sources:
   [MCP.Directory design MCP roundup](https://mcp.directory/blog/best-mcp-servers-for-design-2026),
   [Framelink review](https://chatforest.com/reviews/framelink-figma-mcp-server/).

7. **Visual polish checklist** — modular type scale (Major Third/Golden Ratio), body text ≥15-16px,
   avoid ultra-light gray-on-white (the single most common accessibility complaint is actually a
   typography choice, not a raw contrast-ratio bug). `pbakaus/impeccable` (56k★, maintainer Paul
   Bakaus, actively maintained) packages exactly this as 23 slash-commands (`/impeccable polish`,
   `audit`, `critique`, `harden`, `typeset`, `colorize`, ...) plus a local, no-LLM, no-API-key
   deterministic anti-pattern detector that runs as a `PostToolUse`/`Stop` hook on `Edit`/`Write`.
   Explicitly built as a companion to Anthropic's own `frontend-design` skill, not a competitor.
   Sources: [Humbl Design contrast guide](https://humbldesign.io/blog-posts/color-accessibility-guide-wcag),
   [pbakaus/impeccable](https://github.com/pbakaus/impeccable).

## What was actually done (see `decisions/2026-08-06-install-design-plugins.md` for full reasoning)

- **Installed** `frontend-design@claude-plugins-official` (official, zero-cost, directly targets
  finding #1).
- **Installed** `modern-web-guidance@claude-plugins-official` (Google Chrome, 130+ web-platform
  best-practice checks including accessibility/screen-reader/keyboard coverage, no API key, local
  TensorFlow.js semantic search, 199 commits/1.7k★, actively maintained) — found during local
  cross-check of the official marketplace's `design`/`development` categories, complements finding
  #3.
- **Added marketplace + installed** `impeccable@impeccable` (finding #7) — verified reputability
  (56k★/3.4k forks/known maintainer), verified its `PostToolUse`/`Stop` hooks (`hook.mjs`, 78
  lines) contain no network calls, no `exec`/`spawn`, purely local static analysis, before
  installing — same bar `pensyve`/`remember` failed to clear on 2026-08-06's skills scan (see
  `skills-seen.md`).
- **Not adopted**: any Figma/design-handoff MCP server (finding #6 — no current use case).
- **Added to `~/.claude/CLAUDE.md`**: a new "UI/UX & product design" section distilling findings
  #1/#3/#4/#5 into standing default behavior (invoke `frontend-design` for real UI surfaces,
  self-critique via screenshot loop when the environment supports it, apply the accessibility
  floor by default, run a quick heuristic pass before calling UI work done) — with an explicit
  scope boundary (doesn't apply to throwaway/internal-only surfaces) so it doesn't read as
  unconditional over-polish, matching the same discipline established for the token-efficiency
  section. See `decisions/2026-08-06-design-workflow-standing-instructions.md`.
